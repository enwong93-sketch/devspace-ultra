## 1. Product mainline and v0.5 boundary

The product mainline is broader than Goal Mode or Auto Compact:

> **DevSpace Ultra is the durable local execution/control substrate that gives ChatGPT Classic and other supported agents a Codex-grade workspace, process, capability, memory, browser, multi-agent and continuity layer without losing public MCP identity or user state.**

v0.5 is the milestone that must make this substrate reliable enough to finish the current ChatGPT Classic work. It is complete only when:

1. the production connector exposes a non-regressive Codex-compatible tool surface plus the legacy aliases needed by cached ChatGPT tool schemas;
2. the Unified Capability Runtime, Skills and the existing shared PowerMem service are reachable from ChatGPT Classic rather than silently disabled by recovery process environment;
3. the retained v0.5 working tree is audited and converged into reviewable commits without deleting unknown work;
4. Stable Gateway/Core remains bounded and can deploy without losing public MCP/OAuth/App sessions or requiring page refresh;
5. Goal/Plan are bound to exact conversations and pass real frontend lifecycle acceptance;
6. delivery-timeout and safety-state recovery uses native evidence, never Retry/refresh/synthetic user messages or fabricated progress;
7. Context Guardian uses exact Classic-native actual usage only;
8. Auto Compact v2 proves true same-conversation compaction with lower exact usage;
9. tests, docs, PowerMem, Git history, package/tag and public release all describe the same behavior.

The wider Codex-parity mainline continues after v0.5: audited import/bridging of the remaining Codex MCP catalogue, richer review/approval semantics, and Codex Harness Computer Use. These are not allowed to replace the v0.5 correctness gates, but they are recorded as the next product track rather than being forgotten as unrelated work.

## 4. Post-v0.5 product mainline

After v0.5 release, continue in this order:

1. **Codex MCP catalogue bridge:** discover/import supported entries from the user’s existing Codex MCP configuration into DevSpace manifests without copying secrets; default read-only or disabled until explicit trust. High-risk/elevated services remain separately gated.
2. **Tool parity matrix:** workspace/files/processes/review/artifacts/browser/memory/subagents/MCP resources/prompts/instances compared against Codex behavior with real acceptance tests.
3. **Computer Use:** port or reproduce Codex Harness Computer Use as a universal DevSpace capability only after the v0.5 authority/safety foundation is stable.
4. **Installer/productization:** make safe defaults and capability migration portable for other machines, not hard-coded to this computer.
