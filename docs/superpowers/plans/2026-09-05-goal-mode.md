# DevSpace Ultra Goal Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a persistent Codex-style Goal Mode whose ordinary ChatGPT Classic turns each visibly report to the user before a host-supported hidden continuation starts the next assistant turn.

**Architecture:** `GoalRuntime` owns durable Goal/round/continuation state independently from `PlanRuntime`. One persistent Goal Dock owns status and user Pause/Resume/Stop; every Resume or per-round Relay calls app-only backend `devspace_goal_continuation(action="dispatch")`. The backend atomically owns lease claim/ack/release. Before `ClassicGoalHostBridge` invokes ChatGPT Classic's raw native hidden Tool follow-up RPC, it carries `lastRoundReport.reportedAt` into a visible-report commit gate and requires the matching Chat-mode page to report `stream_status=COMPLETE`, non-generating state, and a non-empty visible assistant report after a short settle window. Public background widget `window.openai.sendFollowUpMessage` is deliberately not used because Chat-mode third-party widgets require synchronous user activation. `ClassicPrimaryDebugGuard` provides safe canonical Main-01 port-9721 lifecycle without interrupting an already-running long-lived primary.

**Tech Stack:** Node.js ESM, `@modelcontextprotocol/ext-apps`, MCP Apps bridge, Zod v4, vanilla HTML/CSS/JS, existing DevSpace fixed MCP server and verification harness.

**Spec:** `docs/superpowers/specs/2026-09-05-goal-mode-design.md`

## Global Constraints

- Goal Mode is separate from Plan Runtime and Context Guardian.
- DevSpace Ultra Goal Mode is supported and live-accepted only in ChatGPT Classic Chat mode. Work mode is out of scope and any Work-mode probe is research-only evidence.
- Every physical Goal turn must call `devspace_goal_turn_report` as its final tool call and then produce one complete visible final user report with no further tools; backend continuation dispatch must remain blocked until the matching Chat page proves that report is committed (`stream_status=COMPLETE`, not generating, visible assistant text present, post-report settle window elapsed).
- Automatic continuation must use backend `ClassicGoalHostBridge` raw native hidden follow-up; never use public background widget `sendFollowUpMessage` and never type a synthetic continuation into the composer. CDP is permitted only as the local transport for the raw native host API, not for composer/user-message automation.
- Hidden continuation must not create a visible synthetic user message.
- Goal objective and success criteria are immutable in v1; changed final objective means stop old Goal and start a new Goal.
- Active Goal completion requires evidence coverage for every stored success criterion.
- `blocked` requires 3 consecutive same-fingerprint no-progress reported rounds.
- Model cannot arbitrarily pause/stop; `devspace_goal_control` is used by Goal Dock or on explicit user request.
- Chat Swarm workers must not start/mount user-facing Goal Mode.
- Existing `DEVSPACE_WIDGETS=off` behavior and Plan Card behavior must remain unchanged.
- Update `docs/DEVSPACE-ULTRA-HANDOFF-2026-09-05-V0.5-IN-PROGRESS.md` after every independently verified task.

- [ ] **Step 1: RED test exclusive claim**

- [ ] **Step 2: RED test release/expiry recovery**

`release` with the current lease returns to `pending`. Advance injected clock beyond `dispatchLeaseMs`; next status/claim normalizes expired `dispatching` back to `pending`.

- [ ] **Step 3: RED test ack and round redemption races**

- `ack` changes `dispatching -> dispatched`;
- `roundBegin` accepts matching continuation from either `dispatching` or `dispatched`;

- repeated `roundBegin` with the same consumed continuation is idempotent and does not increment again;
- `ack` arriving after `roundBegin` returns an already-consumed/idempotent result instead of failing destructively.

- [ ] **Step 4: RED test dispatched recovery deadline**
