# DevSpace Ultra v0.5.6 — stale-session cleanup and native Computer Use approval

DevSpace Ultra v0.5.6 removes the final inactive browser-driver source and closes the approval gap between the linked Codex MCP client and OpenAI's bundled `@oai/sky` Computer Use runtime.

## Old schema and source cleanup

The obsolete custom Chrome-extension implementation, bridge source, runtime module, tests, and legacy live gate are deleted from the repository. They are no longer merely hidden from npm packaging. Current Agent instructions and the Computer Use skill refer only to the official `codex_computer_use` route.

Already-open ChatGPT conversations can still hold an immutable cached copy of an older MCP tool list. When one of the nine removed browser tools is submitted from such a session, DevSpace now returns a normal MCP tool result with:

- `code: retired_tool`
- the exact stale tool name
- `replacementTool: codex_computer_use`
- `cachedLegacySchema: true`
- `otherToolsUnavailable: false`

This prevents one stale cached name from being misreported as a failure of the whole DevSpace tool surface.

## Official Computer Use approval relay

The linked Codex MCP client now advertises MCP form elicitation and relays only the currently executing Computer Use approval request back through the exact outer ChatGPT tool call. The route remains:

```text
codex_computer_use
  -> conversation-isolated linked Codex node_repl
  -> OpenAI bundled @oai/sky
  -> native per-app approval
```

The relay is call-scoped and conversation-isolated. Missing approval support fails closed, parallel calls cannot borrow an approval handler, and unrelated downstream MCP tools receive a cancellation rather than another call's approval.

When the outer MCP host reports that form elicitation is unsupported, DevSpace may accept only a low-risk official Computer Use app request under an exact-conversation observe → one action grant. A successful read-only observation creates one five-minute grant for that app and conversation; exactly one state-changing action consumes it. Another mutation requires another observation. High-risk, mismatched, prohibited, audio, cross-conversation, and unobserved requests still fail closed.

For an ordinary browser or another app that the official runtime classifies as high risk, this fallback additionally requires `input.user_authorized_app_control=true` on the read-only observation, and agents are instructed to set it only after the user explicitly requests or confirms control of that app in the current turn. The explicit flag does not bypass app prohibitions or authorize more than one subsequent action.

## Safety boundaries

Computer Use rejects ChatGPT, Codex, terminals, shells, computer-audio approval, connector mismatch, and target-app mismatch. Ordinary Chrome, Edge, Notepad, File Explorer, and other permitted visible apps continue to use the official observe → one action → re-observe workflow. DevSpace does not implement a replacement mouse, keyboard, screenshot, extension, CDP, Selenium, Playwright, SendInput, or PowerShell UI automation driver.

## Acceptance

The release requires the complete DevSpace Ultra regression suite, source-removal and stale-session gates, public-package checks, alternate-port real-Core canary, live native Computer Use observation and action, exact multi-Main progress isolation, post-deploy zero-waiter verification, and preservation of every existing Main page and Blender process/listener.

The Windows public-error integration gate also closes all test HTTP connections before deleting its temporary state, so repeated release verification does not leave an orphan process or depend on delayed keep-alive expiry.
