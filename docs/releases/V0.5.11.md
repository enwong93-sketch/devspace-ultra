# DevSpace Ultra v0.5.11 — bounded Classic Main relay retention

This release fixes the feedback loop that could make long-running ChatGPT Classic Main conversations accumulate hundreds of hidden MCP App relay frames, consume several gigabytes of private memory, and eventually surface HTTP 413, `Internal Server Error`, or message-delivery timeouts.

The visible `DEVSPACE 進度旁白` card is preserved. Its Agent-authored history remains durable and bounded in the Stable Gateway. The release changes only the short-lived ownership transport behind it:

- ordinary `devspace_progress_report` calls no longer mount an MCP App iframe;
- an unbound report returns one explicit `devspace_progress_bind` action, and only that one-time action mounts the hidden claim relay;
- completed or expired progress and Goal relays release listeners and DOM state;
- each page retains at most eight fresh progress relays and four fresh Goal relays, with a 150-second retention window;
- exact-page claim resolution remains bounded but can recover a newly mounted claim even on a page that already contains hundreds of stale frames;
- the local reverse-proxy path trusts loopback only, preventing repeated forwarded-header validation errors without widening remote trust.

Regression coverage includes a 700-iframe page, one-time bind metadata, ordinary report metadata without UI, bounded relay cleanup, Goal/Rescue compatibility, full Ultra verification, and an alternate-port Core canary that leaves the production Gateway and Core online.

Existing oversized conversations are not deleted. After upgrade, the corrected overlay retires stale relay DOM; a single controlled page reload may be used to release renderer targets that the old host already detached internally. If an individual conversation still exceeds the upstream request-body limit, Context Guardian carries its active Goal/Plan/checkpoint into a fresh backend conversation without erasing the old history.
