# DevSpace Ultra v0.5.13 — live-safe Classic retention and updater convergence

This release completes the bounded relay-retention repair with a production-proven Windows migration path that keeps existing ChatGPT Classic conversations open.

Long-running Classic Main windows could inherit the installed npm package directory as their process working directory. Windows then refuses to rename that package until every renderer closes. The updater now preserves a legacy scoped root in place as a rollback source, installs the canonical `devspace-ultra` package side-by-side, migrates tasks and shims, and leaves already-open Main processes untouched. Future ChatGPT Classic Main and Worker launches use a stable LocalAppData working directory instead of the package tree.

The update handover now also:

- uses `totalNonStreamActiveRequests` as the authoritative active-work fence, ignoring the updater's own status probe and replayable SSE;
- disables runtime/watchdog triggers during swap and restores their prior enabled/running state;
- snapshots and stops the exact DevSpace process tree, including Caddy and descendant helpers;
- rebuilds `better-sqlite3` in the staged package and opens a real in-memory database before promotion;
- regenerates Stable Gateway and watchdog tasks from the canonical package after a legacy migration;
- keeps rollback state, auth, conversations and runtime profiles unchanged.

Progress retention is now bounded per conversation: up to 48 Agent-authored messages for each conversation, with a 256-message global ceiling. A busy Main can no longer evict every other Main's useful narration history. The visible card remains one card per conversation, while hidden progress relays stay capped at eight and Goal relays at four.

Relay cleanup and claim authority are also Connector-isolated. The exact one-time claim records this installation's ChatGPT App sandbox origin and persists only that bounded origin set. Cleanup touches only frames carrying one of those locally proved origins. Another Connector or another computer—including a separately named DevSpace EXP8740 connection—cannot satisfy a local claim, contribute ownership, or lose its frames just because it uses the same generic resource title. If one claim ever appears through two App origins, ownership fails closed.

Production acceptance preserves the existing Main-01 through Main-05 PIDs, confirms public HTTPS health, runs the canonical package on Gateway/Core, and verifies relay bounds through read-only CDP inspection without navigation or synthetic turns.
