# DevSpace Ultra v0.5.23 candidate

This new immutable candidate includes the native request-body ordering repair
after v0.5.22. Earlier tags, draft archives and their evidence are unchanged.
Packaging remains draft-only until exact-archive real Classic acceptance.

## Native source and final ordering

- A successful original native assistant public `final` / `end_turn` is the
  next-round boundary. UI, transport EOF, an earlier summary and a Rescue user
  message are not substitutes. Semantic Goal decisions remain AI/user-owned.
- When the native POST body is omitted from its observed network event,
  retrieve only that existing allowlisted request using the standard
  `Network.getRequestPostData` command. No request or message is replayed.
- Immediately invalidate older final authority; retain bounded response/EOF
  metadata until exact source admission. Newer requests, navigation, failure,
  disconnect, malformed bodies and overflow discard delayed admission.
- Eight deterministic regressions cover this gap. They do not by themselves
  diagnose a particular production stall or prove automatic continuation.

## Preserved continuation and work safety

The candidate retains the authorized public component continuation with
`scrollToBottom:false`, durable one-shot exact-owner claims, native delivery
correlation, Rescue/next-round separation, process-session-safe Core handover,
work-preserving updater and byte-preserving executable installation.

No private host sender, operator-thread fallback, UI input, forced reload or
Goal-state rewrite is introduced. Transport uncertainty does not become a
semantic blocked Goal. Running older software is not changed by a Git push.

## Acceptance boundary

Source/CI success and verified package installation are separate from actual
Classic automatic next-round work. Stable promotion requires the exact
source/archive-bound record in [continuity acceptance](../CONTINUITY_ACCEPTANCE.md).
Manual recovery, simulated receipts and a successful send acknowledgement
cannot supply that record. Preserve original conversations, files, OAuth,
application processes and active work throughout validation and deployment.
