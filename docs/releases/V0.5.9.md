# DevSpace Ultra v0.5.9 — Windows install and direct-ingress repair

This release repairs the installation path that could leave an incomplete global Git junction or a missing `better-sqlite3` native binding. Windows and the macOS/Linux core-only installer now select the exact tagged GitHub Release archive, verify its SHA-256 digest, check the installed package and CLI, rebuild the native module after `--ignore-scripts`, and load-test it before setup.

DuckDNS setup uses the maintained LAN-bound Caddy ingress path. It derives the WAN address from the router rather than a VPN-sensitive internet-IP service, and sends that address explicitly to DuckDNS. UPnP TCP 80/443 mappings require explicit consent and never replace unrelated mappings. UPnP can create those mappings from the local network without logging into the router's administration page when the router supports and permits it; it is not a password bypass or a guarantee on every router. A router that does not support UPnP can use confirmed manual forwarding plus its public WAN IPv4. Only UPnP fault code 714 means a mapping is absent; a generic HTTP 500 is an error, not a deletion signal. The SOAP request now uses a PowerShell 5.1/7-compatible Content-Type and explicit UTF-8 body.

The setup fixes empty-config StrictMode failure, WinGet Caddy discovery, and a Gateway task/config-directory mismatch. It preserves operator-managed custom Caddy routes in a marked block while keeping the DevSpace backend separate. Existing standalone DuckDNS/Caddy tasks require explicit one-time migration consent; setup backs up task definitions and the Caddyfile, adopts the existing Caddy path, verifies the maintained route, then disables the old tasks.

Canonical startup can leave selected interactive runtime slots idle through the installation-local `interactive-runtime-reservations.json` setting. The public product does not identify an external application, import its server endpoint, or treat it as a fallback.

Local Gateway/Core health is reported as local readiness only. Production acceptance still requires independent external HTTPS and OAuth checks, then a ChatGPT Connector initialize, `tools/list`, and an explicitly authorized write-capable call in a disposable workspace. The installer does not claim those external checks succeeded on behalf of the user.

Current installation docs no longer advertise the old upstream `npx @waishnav/devspace` route, port 7676, direct Git URL global npm install, or execution of a moving `main` script. Historical changelog and design specifications remain available as history.
