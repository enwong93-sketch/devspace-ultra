# DevSpace Ultra v0.5.2 — Stable Core, isolated MCP connections, and guided setup

DevSpace Ultra v0.5.2 turns the Local Gateway/Core recovery work into a tested public release and removes the shared-connection assumptions that caused unrelated ChatGPT conversations to interfere with one another.

## Stable Gateway and Core

- Production Core heap sizing is system-managed; legacy 512 MB profiles are migrated rather than enforced.
- Gateway, Core startup, handover, MCP requests, workspace work, and application-runtime work do not use arbitrary wall-clock termination deadlines.
- Gateway keeps its public listener in degraded mode when Core startup fails and retries Core startup without forcing the ChatGPT connector to disappear.
- MCP session descriptors are bounded by real client-session identity and reconnect lifecycle rather than periodic idle cleanup.
- Tool/resource/prompt registration is templated once per Core and reused by lightweight session servers.
- Windows atomic writes retry transient sharing violations instead of crashing the backend.
- Runtime logs are rotated without retaining entire output histories in heap.

## Conversation-isolated connections

- Every ChatGPT conversation receives an independent MCP client/session transport, including linked Codex MCP servers and otherwise stateless providers.
- Stateful application MCPs are additionally bound to conversation, plugin, server, instance, runtime, process, and port.
- Resetting or reconnecting one conversation does not close another conversation's MCP client.
- An already-open Blender project can be adopted into its owning conversation without restarting Blender or replacing the current `.blend` file.
- New concurrent Blender projects receive separate runtime IDs, loopback ports, processes, and private instance tokens.

## Live Blender execution

- `blender_runtime` owns start, attach, status, release, and stop lifecycle.
- `blender_mcp` is the actual execution entry point and exposes the selected runtime's live Blender schema before calling tools such as `execute_blender_code`, scene summaries, screenshots, renders, and saves.
- Omitted `runtimeId` resolves only the current conversation's unique/default assigned runtime and never falls back to a backend-wide shared Blender connection.

## Agent-authored progress narration

- Each interactive ChatGPT conversation owns exactly one floating narration card.
- `devspace_progress_report` binds to the authoritative current conversation; an Agent cannot select another conversation ID.
- Visible text is written by the working Agent in natural language after a meaningful medium-sized step, important verification, direction change, or genuine blocker.
- Timers, tool counters, raw handler boundaries, heartbeat prose, and Goal/Plan telemetry cannot manufacture visible narration.

## One-command setup and guided Skill

- The root `install.ps1` installs/reconciles supported Node.js, Git, the tagged DevSpace Ultra package, the setup Agent Skill, Stable Gateway/Core tasks, and the selected public ingress.
- DuckDNS/DDNS with Caddy is the recommended direct route.
- A stable Cloudflare named tunnel is the fallback for CGNAT or unavailable port forwarding; Worker-relay use is explicitly documented as plan/quota governed.
- Provider secrets are entered through masked local prompts or process-scoped environment variables and persisted only as Windows DPAPI-protected values.
- The separately installable `devspace-ultra-setup` Agent Skill executes safe local work and guides the user through unavoidable DuckDNS account, router, ISP, and OAuth actions one step at a time.

## Conservative safety defaults

`autoCompactEnabled` and `goalRoundRecoveryEnabled` remain `false` in the public installer. Their deterministic contracts remain available for development, but automatic production activation is deferred until dedicated re-entry, prepare/commit/rollback, 429 circuit-breaker, and no-navigation live acceptance is complete.

## Verification

The release branch passed:

- the complete `npm run verify:ultra` suite;
- public-package, private-path, credential, and package-content gates;
- real alternate-port Core startup with 123 callable tools;
- OAuth-authenticated `tools/list` verification for `blender_runtime`, `blender_mcp`, `capability_connection`, `devspace_progress_report`, routing, and authority tools;
- Stable Gateway, session descriptor, MCP lifecycle, memory isolation, Context Guardian, Plan, Goal, progress overlay, and stream-recovery gates;
- Blender runtime adoption, dual-runtime isolation, linked Codex connection isolation, and graceful shutdown tests.
