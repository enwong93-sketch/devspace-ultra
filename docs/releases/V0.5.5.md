# DevSpace Ultra v0.5.5 — exact conversation recovery and native Computer Use

DevSpace Ultra v0.5.5 closes the remaining production gaps around long-running direct MCP calls, multi-Main conversation identity, Goal Recovery, and browser automation while preserving every existing ChatGPT page and Blender process during Core upgrades.

## Exact direct-tool authority

ChatGPT can invoke MCP tools from a server-side transport that is not mirrored by the older browser `call_mcp` request. DevSpace now joins browser turns and direct tool requests only through bounded, hashed trace/session evidence and an exact live conversation-page check.

- `devspace_progress_report`, Goal/Plan, Blender routing, and Codex Computer Use no longer wait indefinitely for a browser request that may never exist.
- Every correlation waiter is request-scoped, cancellable, bounded, and removed after success, timeout, abort, or ambiguity.
- A verified direct session can be reused across later trace groups only while its exact conversation page remains present and valid.
- Conversation completion or cancellation revokes inherited direct-request authority.
- Raw session descriptors, request traces, prompts, and tool arguments are not persisted.

When one Main Runtime navigates from an older conversation to a new one, the next exact browser turn replaces the stale route. The same conversation may also move to another Runtime. A session observed across both a different conversation and a different Runtime remains ambiguous and fails closed.

## Minimal interruption rescue and Goal Recovery

The ten-minute rule remains an Agent-authored reporting ceiling only; no timer emits a reminder or synthetic user turn.

A twenty-minute rescue is eligible only for an exact conversation with verified interruption/incomplete-turn evidence. Its only visible text is:

```text
- 繼續
```

All ownership, timing, deduplication, composer, completion, and cancellation checks remain backend-owned. A committed rescue is never repeated for the same interruption episode.

Goal Recovery is enabled through the same exact-page composer transport, but remains independently gated by the Goal round state. It does not foreground or open a window, navigate or reload a page, run Primary repair, select by Runtime alone, or retry after a committed send.

## Native browser and Computer Use

The former custom Chrome-extension `browser_control_*` execution path is retired. Ordinary Chrome, Edge, and Windows GUI work routes through:

```text
codex_computer_use
  -> persistent linked Codex node_repl
  -> OpenAI bundled @oai/sky
```

Retired Browser Control runtime files are excluded from the public tool surface and release archive. The legacy endpoint returns HTTP 410 with `codex_computer_use` as the replacement.

## Release hygiene and verification

The npm package excludes local `.before-*`, `.bak*`, and diagnostic backup artifacts. Public release gates also reject retired browser-driver files, machine-specific paths, private ingress endpoints, and literal credentials.

The release is accepted only after the complete `verify:ultra` suite, focused direct-tool and multi-Main regression tests, Goal/Plan/Recovery gates, Codex Computer Use and native browser gates, Stable Gateway replay/schema tests, public package checks, an alternate-port real Core canary, post-deploy waiter cleanup, and production identity checks. Core deployment must preserve all existing Main page IDs/URLs and all Blender PIDs, creation times, loopback listeners, ownership, and scenes.

Auto Compact remains disabled in production pending its separate user-authorized re-entry decision.
