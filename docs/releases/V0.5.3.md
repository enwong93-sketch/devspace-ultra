# DevSpace Ultra v0.5.3 — Main tool delivery, isolated Blender routing, and timestamped progress

DevSpace Ultra v0.5.3 closes the gap between a healthy backend tool catalogue and a specific ChatGPT Main turn that receives only a lazily selected subset of deferred tools.

## Blender Runtime correction

- Conversation-owned Blender runtimes now pass the official Blender Lab MCP environment variables `BLENDER_MCP_HOST` and `BLENDER_MCP_PORT`.
- Legacy `BLENDER_HOST` and `BLENDER_PORT` aliases remain for community servers.
- Every claimed Blender connection carries an explicit `instanceId` and `runtimeId`.
- Existing user-opened Blender processes are preserved. The compatibility path cannot start, stop, replace, or guess between runtimes.

## Host lazy-tool compatibility bridge

The package now installs a `devspace-conversation-bridge` executable. When ChatGPT exposes `exec_command` but omits a deferred `blender_runtime`, `blender_mcp`, or `devspace_progress_report` function from one turn, the working Agent can continue without reconnecting or replacing the application runtime.

The bridge:

- resolves the latest non-ambiguous native conversation authority for the selected Main runtime;
- rejects cross-conversation Blender access;
- checks the existing process and loopback listener;
- opens an isolated DevSpace CapabilityRuntime connection with the assigned runtime port;
- invokes only tools from the live Blender MCP schema;
- routes narration through the Stable Gateway progress endpoint so atomic serialization and normal source validation remain intact.

## Progress-card timestamps

Each stored Agent-authored progress message is rendered with its own browser-local `[YYYY-MM-DD HH:mm]` timecode. Timestamps come from the persisted message event rather than the current render time, so reopening or scrolling the card does not rewrite history. Agent prose remains free-form and is still written only at meaningful medium-sized steps, verification results, direction changes, or genuine blockers.

## Verification

Release gates cover conversation authority, Blender runtime ownership, official MCP port variables, live read-only Blender calls, public package/bin inclusion, serialized progress writes, timestamp rendering, the complete DevSpace regression suite, a real isolated Core/Gateway OAuth + MCP + handover canary, and production memory/PID soak.

Automatic Goal Recovery and Auto Compact remain disabled by default pending their separate production re-entry and transaction gates.
