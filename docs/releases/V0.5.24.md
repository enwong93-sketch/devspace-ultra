# DevSpace Ultra v0.5.24 candidate

This immutable candidate adds authoritative native conversation-API final
readback and shared-runtime-safe transactional updates. Prior tags, archives
and their acceptance records remain unchanged.

## Native Goal continuation

- Admit only the exact current conversation's successful public assistant
  final with explicit `end_turn`. UI idle, summaries, send acknowledgements
  and HTTP silence cannot authorize another round.
- Re-read native API evidence when SSE completion envelopes are absent;
  newer requests and navigation invalidate stale evidence.
- Preserve complete scoped receipts through persistence. Admit already-issued
  public continuations only after their exact native assistant work starts.
- Keep semantic Goal completion AI/user-owned; optional checkpoints are not
  completion prerequisites. Rescue remains separate from next-round delivery.
- Retain v2 Goal/progress resource URIs used by older saved tool results and
  notify connected clients of resource-list changes. Host cache invalidation
  is not a promise that a closed or cached App view has mounted/refreshed.
- Existing-Goal mount restores the hidden continuation component, not merely
  its floating label. It requires the original verified caller, leaves Goal
  state unchanged and does not send a message or require an optional report.
- Already-consumed completed finals use a lower-frequency API audit. Exact
  native request/transport hints wake sampling immediately, but cannot close
  a turn themselves. Working/unresolved input retains the normal cadence.

## Work-preserving updates

- Retire only exact package-owned processes, in child-first order. Preserve
  shared Caddy, native ChatGPT applications, ingress and canonical startup.
- Refuse retirement when an owned tree contains a protected application.
- Preserve config, OAuth, files and runtime state with transactional rollback.
  HTTP and process counters alone are not a native maintenance-window proof.
- Re-read each operator-declared Gateway Classic owner's native final twice
  after staging, verify unchanged page/branch ownership, then recheck Core work
  before retirement. Unknown live membership defers, including automatic runs.
  This is not an atomic barrier against new human submissions during maintenance.
- Maintenance observes two real, uncached replies from the existing native
  reader instead of inducing duplicate GETs. HTTP 429 remains unavailable
  evidence, not proof of completion; successful replies retain all final checks.
- Continuation arming and its eligibility rechecks reuse the completion
  sampler's own successful read of the same native final for at most two
  minutes while that page has had no new native request, instead of each
  issuing another whole-conversation GET that the provider answers with 429.
  The sampler and the dispatch preflight still read again every time.
- A checkpoint for a round its native final already closed now returns the
  unchanged Goal instead of a content-less error, so the continuation
  component rendered for that call can start. Nothing is recorded.

## Acceptance boundary

Source, fixtures, CI and package checks are not real-client automatic
continuation acceptance. Stable promotion still requires the exact-archive
record described in [continuity acceptance](../CONTINUITY_ACCEPTANCE.md).
No private machine evidence or simulated attestation is shipped.
