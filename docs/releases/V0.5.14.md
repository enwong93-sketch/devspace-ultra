# DevSpace Ultra v0.5.14 — multi-computer MCP instance isolation

One cloud ChatGPT Classic account can connect several DevSpace MCP servers, with each server exposing a different computer through its own DDNS or stable tunnel. This release makes that a first-class, fail-closed public product contract.

Every installation now persists a unique `serverInstanceId`. Legacy configurations receive a deterministic fallback derived from the exact public `/mcp` resource until setup persists an independent random identity. OAuth continues to require the exact configured resource audience.

For ChatGPT Connector traffic, every non-bootstrap tool call must carry a current exact invocation observed on a local ChatGPT Classic Runtime page for that server instance. A same-named connection on another computer, stale provider binding, reused cloud account session, matching conversation ID or matching tool name is not enough. Unbound or wrong-computer calls return `devspace_instance_binding_required`; only the local one-time progress/Goal/Plan bootstrap is allowed, and it cannot complete unless this computer's CDP observer sees the Connector App under the exact local page.

Hidden relay cleanup is scoped by the complete persisted instance boundary: `serverInstanceId + public resource origin + proved ChatGPT App sandbox origin`. If one claim appears through two Connector App origins, resolution fails closed. A separate connection such as DevSpace EXP8740 can therefore coexist on the same ChatGPT account without donating authority, satisfying local claims, sharing Goal/progress state, or losing its iframe resources.

This release includes the v0.5.13 live-safe updater, side-by-side legacy migration, native SQLite stage validation, stable runtime working directories, per-conversation progress retention, bounded relay cleanup and exact stuck-turn recovery tools.
