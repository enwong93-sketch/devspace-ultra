# DevSpace Ultra v0.5.18 — restore existing Classic conversations

This release fixes the remaining `devspace_instance_binding_required` regression after v0.5.17. An existing ChatGPT Classic conversation with a previously proved provider binding can use ordinary tools after reconnect because the server rechecks that authenticated binding against the exact live local Classic page on every request. A current exact invocation remains valid too.

New conversations still use one exact-page bootstrap. When a progress report returns a pending claim, the Agent follows its `devspace_progress_bind` next action once. No user-side pairing is required. Unbound identities, missing or duplicate local pages, different OAuth resources, and another computer's Connector remain rejected.

Live acceptance on a local ChatGPT Classic runtime confirmed that `devspace_progress_report` and `devspace_plan_status` returned success in the same turn after the repair. Focused provider-binding and server-instance isolation tests cover wrong resources and absent local proof.
