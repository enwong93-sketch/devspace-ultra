# DevSpace Ultra v0.5.7 — exact conversation ownership for tools, progress and rescue

DevSpace Ultra v0.5.7 closes the remaining cross-conversation authority gap in ChatGPT Classic. A direct MCP session, distributed trace, Runtime number, open page, or prior successful call can no longer become a reusable conversation owner.

## Exact page-local tool invocation authority

ChatGPT may use one host-side direct MCP transport across several open conversations. DevSpace therefore no longer treats the host session as the identity of a conversation. For every conversation-bound tool call it now requires a bounded join between:

1. the exact ChatGPT page route that emitted the tool invocation;
2. the canonical DevSpace tool name and argument hash observed in that page's response or WebSocket stream;
3. the canonical name and argument hash received by one current Stable Gateway request; and
4. a final verification that exactly one hydrated, generating page still owns that conversation and that its floating card is not mounted for another conversation.

The join is request-scoped. Each Gateway request receives a unique internal correlation ID, so a later call with identical arguments cannot reuse a previous resolved owner. Equal-distance or multi-page ambiguity fails closed.

## Durable authority removed

The release deletes the old cross-request direct-trace registry and removes the verified direct-session writer and lookup. It also removes Runtime-only, tool-name-only, session-alias, and deferred-placeholder ownership fallbacks. Runtime remains only a verified physical page locator after the conversation has already been selected by exact evidence.

Browser-turn traces remain available for liveness and diagnostics, but they do not authorize server-side direct tools. Raw tool arguments, prompt content, message IDs, request IDs, session values, and trace IDs are not stored.

## Progress-card cutover and rescue repair

Agent-authored progress now carries a versioned ownership proof:

- `exact-conversation-request-v1` for a normal direct tool request;
- `exact-page-compatibility-bridge-v1` for the explicit exact-page compatibility bridge.

New Agent progress without a valid proof is rejected. Historical rows written before this fix are preserved for diagnostics, but they are not projected into any floating narration card and cannot update another conversation's ten-minute reporting state or twenty-minute rescue episode.

The liveness state format advances to version 4. Older armed episodes are disarmed during upgrade rather than inheriting potentially polluted progress timing. The visible rescue message remains exactly:

```text
- 繼續
```

The backend still requires an exact conversation page, verified interruption, an empty composer, at least twenty minutes, and no prior committed rescue in the same episode. Normal completion, explicit cancellation, or genuine resumed work disarms the episode.

## Bounded stream processing

The Classic transport observer reads the owning conversation's live response stream and WebSocket events without DOM ownership guesses or page control. UTF-8 decoding is incremental, so a Traditional Chinese tool argument split across network chunks remains intact. Parsing retains at most a 512 KiB tail for each of no more than 16 concurrent responses per Main Runtime, and duplicate copies of one tool message are suppressed by a hashed invocation identity.

## Acceptance

Release acceptance covers shared host sessions used by two conversations, simultaneous identical progress calls, direct-tool timeout cleanup, exact page verification, old-row projection cutover, rescue-state migration, Goal and Plan ownership, Stable Gateway handover, Context Guardian, Host Overlay, Stream Recovery, native Computer Use, capability and Blender isolation, public package checks, and an alternate-port real-Core canary.

Production deployment must preserve every existing Main page, conversation URL, Blender PID/listener and other Agent Runtime. Chat to Codex and other projects remain outside the DevSpace Ultra release tree.
