# DevSpace Ultra v0.5.8 — conversation-stable execution and canonical startup

DevSpace Ultra v0.5.8 makes long ChatGPT Classic work survive the ordinary events that previously broke continuity: deferred tool calls, MCP schema refresh, renderer reload, hidden Goal continuation, Stable Gateway recovery and Windows sign-in startup.

## Active-turn tool authority

Direct workspace tools now remain attached to the exact active native ChatGPT turn. DevSpace carries that bounded request authority through deferred calls and schema refresh without turning a durable MCP session, previous request, Runtime number or earlier conversation into a reusable owner.

When the host refreshes its tool list, writable DevSpace tools are ranked ahead of read-only and compatibility aliases. The owning conversation therefore keeps real edit, patch and execution capability instead of silently degrading to an inspection-only surface.

## Exact progress, Goal and recovery claims

Agent-authored progress uses an exact-page claim and a bounded relay into the current conversation. Goal, Plan and floating narration can remount after a renderer reload while remaining bound to the same conversation.

Automatic Goal continuation and hidden resume observation use the same exact ownership boundary. They do not activate a window, navigate or reload a page, select by Runtime alone, or write into another conversation. A committed recovery is not duplicated, and normal completion or cancellation disarms the episode.

## Canonical Windows startup

The new `DevSpace-Canonical-Startup` logon task starts only the production control plane and the five user-facing Main runtimes:

- Stable Gateway and protected local ingress;
- canonical Main-01;
- independently profiled Main-02 through Main-05, staggered and minimized.

Each secondary Main must pass signed-in and isolation verification. Worker runtimes, Chat Swarm autojoin and Worker Auto Compact are explicitly excluded from this startup path.

## Session and ingress hardening

MCP sessions now remain available across model-surface refresh when the live conversation still owns them. Canonical runtime recovery preserves existing Main pages, and local ingress startup verifies its loopback listener and protected configuration before reporting ready.

The release adds deterministic gates for exact progress claims, active-turn direct tools, schema refresh, hidden Goal resume, no-navigation recovery, overlay remounting, canonical startup and Main/Worker lifecycle separation.

## CI and release integrity

GitHub Actions now uses `npm ci` with native dependency scripts enabled. This tests the real `better-sqlite3` OAuth/state boundary on Windows, macOS and Linux instead of producing a false failure from a missing native binding.

The release continues to run the public-package, Stable Gateway, capability, Classic safety and version-consistency gates before publishing its installer scripts, npm-compatible archive and checksums.
