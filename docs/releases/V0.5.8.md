# DevSpace Ultra v0.5.8 — conversation-stable execution and canonical startup

DevSpace Ultra v0.5.8 makes long ChatGPT Classic work survive the ordinary events that previously broke continuity: deferred tool calls, MCP schema refresh, renderer reload, hidden Goal continuation, Stable Gateway recovery and Windows sign-in startup.

This same v0.5.8 release also includes the later maintenance refresh for the floating progress narration surface and conversation-authority cleanup. The version remains `0.5.8`; no `0.5.9` version was introduced for these fixes.

## v0.5.8 maintenance refresh

- Interrupted-turn rescue now advances its twenty-minute silence clock only for substantive DevSpace tool requests that the Local Gateway actually admits after the progress preflight. A raw page-observed tool attempt that is subsequently blocked for stale or missing narration no longer postpones rescue, and transport-only HTTP `loadingFinished` remains non-terminal without moving `lastActivityAt`.
- Blender runtimes are no longer hard-owned by the ChatGPT conversation that first attached them. The authoritative identity is now the Blender `runtimeId`, process and loopback MCP port, allowing a fresh conversation to continue the same open `.blend` and MCP session after context-limit handoff. Existing v2 runtime state migrates its former `ownerConversationId` to an advisory `lastConversationId` hint. When exactly one Blender runtime is online it can be resumed directly; when several are online DevSpace still requires an explicit `runtimeId`, preserving project/process isolation without blocking legitimate conversation handoff. This exception applies to Blender only—ordinary capability and linked Codex MCP transports remain conversation-isolated.
- Progress narration is now hard-enforced for exact user-facing Main conversations instead of relying only on Agent instruction-following. When a Main has an active multi-step Plan, substantive tools are rejected until the current turn has a verified Agent-authored progress report. Without a Plan, one substantive tool remains the atomic exception, but a second substantive tool requires narration first. A report older than the ten-minute ceiling blocks the next substantive phase, and a Plan cannot transition to fully completed until a fresh verified report exists. Exact-page bridge reports satisfy the gate through the same durable ownership proof; Main-01 through Main-05 share the policy, backend Chat Swarm workers are excluded, and the gate never generates narration text on the Agent's behalf.
- The first direct `codex_computer_use_status` or `codex_computer_use` call no longer depends on a race with the native tool-correlation stream. If that stronger correlation has not arrived yet, DevSpace accepts only one request-scoped fallback: exactly one hydrated Main page must be actively generating, have an empty composer, and own the progress card for its own conversation. Duplicate active pages, an idle page or a mismatched card owner fail closed, and the result is never persisted as reusable session authority.
- ChatGPT Classic now shows a conversation-scoped blue takeover state while the official bundled `@oai/sky` runtime is observing or operating a permitted Windows app. It identifies the target app and current action, states that the boundary is limited to the current conversation, never blocks the user's mouse or keyboard, keeps one bounded session across adjacent observe/action calls, arbitrates one Core producer, and clears after ten idle seconds or a hard timeout. This is a DevSpace visibility layer only—the actual screenshot, accessibility and input work remains entirely in OpenAI's `@oai/sky`; ChatGPT, Codex, terminals and authentication/security UI remain prohibited targets.
- Computer Use now has an explicit end-of-control handshake. Before returning control to the user, the Agent performs one final read-only observation with `input.release_control=true`; DevSpace immediately removes the blue takeover state and releases its page-local ownership. Mutating calls cannot release directly, preserving the required action → re-observe discipline, while failed Computer Use operations clear the takeover state automatically as a fail-safe.
- Long-running Main turns now keep authority across the real ChatGPT tool boundary instead of treating a transient `generating=false` UI state as proof that an exact page-local tool invocation is invalid. The weaker session/active-turn fallback remains stricter and still requires a currently generating exact page, so this does not reintroduce reusable cross-conversation session authority.
- Interrupted-turn rescue now distinguishes HTTP transport completion from assistant completion. A normal `loadingFinished` event cannot move a long tool-using turn into `completion-pending`. If an authoritative transport failure leaves ChatGPT visibly stuck behind a stale Stop button, DevSpace waits for the existing twenty-minute rescue threshold plus a second exact-page confirmation, clicks that stale Stop once without navigation or foreground activation, then uses the ordinary one-shot `- 繼續` recovery path. The cancellation event caused by that guarded reset is recognized as part of the same interrupted episode; an actual user cancellation still disarms recovery.
- Agent-authored narration is explicitly required on both sides of long process/CI waits when the wait could otherwise cross the ten-minute silent ceiling. The supervisor remains diagnostic-only at ten minutes and never invents reminder prose or a synthetic user turn.
- Stable Gateway OAuth-token CI verification now identifies the exact translated request rather than racing an asynchronous schema-fingerprint observation for the final diagnostic row. This removes the intermittent macOS arm64 failure without weakening the credential-rotation assertion.
- Fixed the secondary-Main progress fallback that could leave `DEVSPACE 進度旁白` at `0 段`. The hidden relay was present and callable, but on affected ChatGPT Desktop pages `window.openai.toolOutput` remained `null`, so the short-lived claim never reached DevSpace and expired. The progress tool now declares its structured result schema and mirrors only the opaque claim descriptor through app-only tool-result metadata. The relay accepts either channel and still requires exact page verification before writing; message text is never copied into metadata and cross-conversation claims remain fail-closed.
- Agent-authored narration now remains visible across later assistant turns and Stable Gateway/Core restarts. The persisted history was already intact, but a thirty-minute projection cutoff could make the card reopen with only the newest row or `0 段`; projection is now bounded by conversation identity and message count rather than message age.
- An armed conversation episode restored after Core replacement now carries explicit restart interruption evidence. A normal assistant completion or fresh native turn cancels it, while a genuinely stuck exact page may reset one stale Stop affordance after twenty minutes and then use the existing one-shot `- 繼續` rescue.
- Existing installations now have a transactional update path. A one-time digest-verified `update.ps1` release asset can migrate builds that predate the updater; after migration, `devspace update` and the `DevSpace-Ultra-Auto-Update` Scheduled Task keep the installation on the latest stable GitHub Release.
- The updater stages and syntax/version-checks the release archive before touching the live package, preserves config/auth/conversation/runtime state, migrates legacy `@waishnav/devspace` package layouts, keeps on-volume package/shim backups and restores them automatically if post-swap verification fails.
- Automatic runs never interrupt active non-stream Agent/tool work. Same-version maintenance payloads are compared by release archive SHA-256, allowing this corrected `0.5.8` release to repair an earlier `0.5.8` payload without inventing a new semantic version.
- The floating progress narration card now arbitrates one page-local producer before any DOM mutation. Stable Gateway active Core has priority 100, an ordinary standalone Core priority 10 and a candidate Core priority 0. A stale orphan Core can no longer alternate card size/content with the production Core and cause visible flashing.
- Interactive Main tasks now receive a mandatory opening progress preflight in every Local Gateway instruction mode. A pending or unbound report claim is not treated as a successful visible update; the exact-conversation compatibility bridge remains the verified fallback.
- Persisted legacy verified-direct-session rows from the older authority model are discarded on load instead of merely having their verification bit cleared, preventing an old open page from reusing a stale session-to-conversation route.

## Active-turn tool authority

Direct workspace tools now remain attached to the exact active native ChatGPT turn. DevSpace carries that bounded request authority through deferred calls and schema refresh without turning a durable MCP session, previous request, Runtime number or earlier conversation into a reusable owner.

When the host refreshes its tool list, writable DevSpace tools are ranked ahead of read-only and compatibility aliases. The owning conversation therefore keeps real edit, patch and execution capability instead of silently degrading to an inspection-only surface.

## Exact progress, Goal and recovery claims

Agent-authored progress uses an exact-page claim and a bounded relay into the current conversation. Goal, Plan and floating narration can remount after a renderer reload while remaining bound to the same conversation.

Automatic Goal continuation and hidden resume observation use the same exact ownership boundary. They do not activate a window, navigate or reload a page, select by Runtime alone, or write into another conversation. A committed recovery is not duplicated, and normal completion or cancellation disarms the episode.

## Canonical Windows startup

The new `DevSpace-Canonical-Startup` logon task starts only the production control plane and the five user-facing Main runtimes:

- Stable Gateway and protected local ingress;
- canonical Main-01;
- independently profiled Main-02 through Main-05, staggered and minimized.

Each secondary Main must pass signed-in and isolation verification. Worker runtimes, Chat Swarm autojoin and Worker Auto Compact are explicitly excluded from this startup path.

## Session and ingress hardening

MCP sessions now remain available across model-surface refresh when the live conversation still owns them. Canonical runtime recovery preserves existing Main pages, and local ingress startup verifies its loopback listener and protected configuration before reporting ready.

The release adds deterministic gates for exact progress claims, active-turn direct tools, schema refresh, hidden Goal resume, no-navigation recovery, overlay remounting, canonical startup and Main/Worker lifecycle separation.

## CI and release integrity

GitHub Actions now uses `npm ci` with native dependency scripts enabled. This tests the real `better-sqlite3` OAuth/state boundary on Windows, macOS and Linux instead of producing a false failure from a missing native binding. The Windows-only local-ingress regression is wrapped by a platform gate, so non-Windows jobs skip that one operating-system-specific probe while still running every portable release gate.

The canonical Main-01 debug guard is also instantiated only on Windows. Portable server and OAuth tests on macOS and Linux no longer require Windows snapshot/repair adapters, while the Windows runtime retains the full guarded startup and recovery path.

The twenty-minute interrupted-turn rescue now also recovers the host failure mode where an exact ChatGPT page remains visibly `generating` indefinitely without a transport error. After twenty minutes with no Agent-authored report and no newly observed substantive tool invocation, a page whose latest visible turn is still the user's request may be classified as `stalled-generating`; a second exact-page observation is required before DevSpace resets the stale Stop affordance and uses the existing one-shot `- 繼續` rescue. Fresh activity resets only that conversation's clock, concurrent Main runtimes remain isolated, and a Core restart preserves elapsed silence instead of starting another twenty-minute wait.

The process-session regression now treats output and process exit as separate asynchronous events. It accepts the legitimate case where the last output chunk arrives immediately before the close event, then performs a bounded follow-up poll before verifying resource disposal.

Workspace-memory checks now preserve platform filesystem semantics. Every platform verifies exact-root context reuse, and Windows additionally verifies case-insensitive path aliases without imposing that Windows rule on Linux or macOS.

The release continues to run the public-package, Stable Gateway, capability, Classic safety and version-consistency gates before publishing its installer scripts, npm-compatible archive and checksums.
