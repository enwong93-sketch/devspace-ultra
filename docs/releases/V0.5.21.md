# DevSpace Ultra v0.5.21 candidate

This is a new immutable release identity for the native Goal continuation
repair. It does not replace the existing v0.5.20 tag or its archive. Tag builds
remain draft-only until the separate evidence-checked stable promotion.

## Native Goal continuation

- A successful native assistant `final` / `end_turn` event is the turn boundary.
  DOM appearance, idle time, Stop buttons and summary-looking prose are not.
- The user-authorized public component bridge sends one continuation in the
  original conversation using `sendFollowUpMessage` with `scrollToBottom:false`.
  It does not manipulate the composer, focus, navigation or private host APIs.
- Durable exact-owner claims prevent competing components and restarts from
  issuing the same continuation twice. A send acknowledgement alone is not a
  new working round. Authenticated round-begin or a correlated native final
  supplies the delivery evidence; semantic Goal decisions remain AI/user-owned.
- Rebooted Main identity can reconcile an external continuation without
  falsely recording human recovery as an automatic pass. The relay resource
  is v3; existing components are not forcibly reloaded or injected.

## Work and installation preservation

- Authenticated workspace image reads retain path-containment checks without
  requiring a live page claim that ordinary workspace reads do not need.
- Core handover checks the exact old PID and zero retained process sessions
  before candidate startup and again after request admission closes. An HTTP
  quiet period alone must not terminate background commands or discard output.
  Busy or unavailable diagnostics defer handover without changing Goal state.
  Already running older Gateways do not gain this guard automatically.
- Executable shebangs ship with LF line endings so npm does not rewrite the
  archive's bytes during installation. Existing dependency security fixes and
  the v0.5.20 Classic installation-contract threshold are preserved.

## Acceptance boundary

Source regression tests, backend canaries and package hash verification are
not original-client acceptance. Stable promotion still requires the exact
source/archive-bound record in [continuity acceptance](../CONTINUITY_ACCEPTANCE.md),
including actual automatic subsequent work, Rescue, Core continuity and
installation/upgrade. Do not publish a successful stable claim from simulated
receipts, manual continuation or an unverified transport acknowledgement.

No original conversation, Goal, project files or active background job may be
discarded to obtain acceptance. Missing public API capability or a platform
rejection must not be bypassed.
