# DevSpace Ultra v0.5.4 — replayable-stream-safe Core handover

DevSpace Ultra v0.5.4 fixes a production handover starvation condition without weakening the no-timeout policy or interrupting live Agent work.

## Quiet-boundary correction

ChatGPT keeps long-lived MCP event streams open so a conversation can receive tools, progress, and app events. These replayable streams are continuity infrastructure, not unfinished tool work. Earlier builds counted them inside the MCP-session active-request total used by the detached Core handover worker. A healthy installation with several open Main conversations could therefore wait forever even when every real tool call had finished.

The quiet gate now computes:

```text
non-stream session work = total active MCP requests - replayable event streams
```

Gateway HTTP admission and every non-stream MCP request must still reach zero for two consecutive observations. There is no wall-clock deadline. Replayable streams remain registered and are replayed onto the replacement Core by the existing Stable Gateway session handover path.

## Preserved safety properties

- The public Gateway listener is never restarted for an ordinary Core upgrade.
- Existing Blender processes, files, runtime IDs, loopback ports, and conversation ownership remain untouched.
- A real tool request still blocks handover until completion.
- A pure event-stream population no longer blocks forever.
- Authentication, schema compatibility, rollback, session replay, and partial stale-session isolation remain mandatory.
- Core heap sizing stays system-managed; no artificial workspace, session, or task timeout is introduced.
- Goal Recovery and Auto Compact remain disabled by default pending their separate live acceptance gates.

## Verification

The release passed the complete DevSpace regression suite, the focused Stable Gateway suite, a real isolated OAuth + MCP Core A→B canary, the public package/release gates, and a five-minute production Core soak with stable PID, bounded descriptors/correlation waiters, zero new OOM signatures, and zero new fatal Core errors.
